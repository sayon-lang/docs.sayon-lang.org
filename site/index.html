Sayon's documentation

Programming made easy. Safety made automatic.

The guides to Sayon, which will be published at docs.sayon-lang.org:

  • Installing: installers for each device, what they change, and uninstalling
  • The language: a reference for everything implemented so far, from values and ownership to projects, packages, and targets

The references that change with the compiler stay beside its code, in sayon-lang/sayon:

  • Feature ledger: what exists, what is planned, and for which milestone
  • Error codes: what each diagnostic and runtime error code means, also shown by sayon explain CODE
  • Implementation records: grammar, ownership rules, cleanup order, data layouts, and the error ABI
  • Licenses: what is not Sayon's own in its files and in the programs it builds

The package registry's protocol is in packages.sayon-lang.org.

Writing here

These pages describe Sayon as it is implemented: a change to the language goes with a change here. Each page is Markdown that GitHub shows as it is, and a Sayon program makes the site from the same files:

sayon run
sayon test

sayon run writes site/: each guide's page, in the layout of src/layout.sayon, with the files of static/ (the stylesheet and the logo) beside them. src/markdown.sayon reads Markdown as these pages write it: headings with the ids GitHub gives them, paragraphs, lists, tables, code (Sayon's highlighted by src/highlight.sayon), and in text code, strong, emphasis, and links, those to another guide made links to its page. sayon test runs its tests, and checks that site/ holds what the program makes, so a change to a page goes with its HTML. site/ is plain HTML and CSS that any static host serves; to see it:

python -m http.server 8000 --directory site
